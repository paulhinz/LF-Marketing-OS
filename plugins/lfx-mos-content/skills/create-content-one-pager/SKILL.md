# Create content: one-pager

Read the shared rules first: the content-core skill. Follow its step 1 (brief, guided or your own prompt, and cancel), step 2 (sources of truth, including references and, when it exists, curated content), 2a (companions), 3 (plan), 4 (voice and the clean asset), 5 (build and accessibility), 6 (self-review), 7 (the asset and its separate metadata record), 7a (revise, edit and delete) and 9 (hygiene). This skill adds only what is specific to a one-pager.

## What is specific to a one-pager

- One page: the message house, the 50-word boilerplate, proof points with time frames, and one call to action.
- If the brand-positioning plugin's one-pager skill applies (lfx-mos-brand-positioning:one-pager), use it rather than rebuilding the page, then run the self-review (core step 6) on its output.
- Format: the host's design type, a hand-built page, or Codesign for a print PDF. Look at the render before handing it over.
- Letter size unless the person asks for another size. Ask the print size only if it will be printed.
- Metadata fields to fill: built_from, placeholders, please_confirm, refresh_before_publishing, files.

## Copy-ready brief

```
Create a one-pager with the Marketing OS create-content-one-pager skill.

Project: [project name]
Audience: [e.g. prospective members, partners, press]
Goal: [what the reader should do afterwards]
Call to action and link: [e.g. join as a member]
Proof points to include: [with a source and date for each; or leave blank to use the key numbers]
Anything to avoid: [topics, partner names, claims]
Sources and references (optional): [links, uploaded files, pasted text]

Use the project's message house, 50-word boilerplate and brand kit.
Give me a one-screen plan first, then the page.
Return status, sources, anything to confirm and the final files as a separate metadata record, not on the page.
```
