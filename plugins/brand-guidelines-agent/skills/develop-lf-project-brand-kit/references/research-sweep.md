# Beyond-the-brief research sweep

The intake interview and the README are what the requester remembers. The sweep
is what a marketer with one afternoon finds. In the x402 run the agents never
opened the site's Get Involved page (four named working groups), the facilitator
directory (fifteen production integrators, several of them members), the
intent-to-launch press release (the real origin story), the originator's own
announcements (a year-old official integration with a member's protocol), or a
competitor search (a Premier member's like-for-like protocol, six months old).
Run the sweep before drafting, and record it, so the sibling agents inherit it.

## Sources to open, in order

1. **The project site, every top-level navigation item.** Get Involved (working
   groups, meeting calendar, mailing lists, Slack), Members (tiers, published
   pricing, benefits, current roster — the public source for any external
   roster), Announcements and Blog (dates, quotes, adopters), Docs (directories:
   integrators, facilitators, network or platform support, ecosystem tools).
   Record exact URLs and anchors; the CTA library needs them.
2. **The GitHub organization.** README, CONTRIBUTING, ROADMAP, LICENSE, specs,
   GOVERNANCE or MAINTAINERS, the other repositories. Count packages and
   components yourself.
3. **The LF press archive.** Search linuxfoundation.org/press for the project.
   Usually two releases: intent to launch (founding members, origin, who
   designed governance) and operational launch (member count, named members by
   tier, executive quotes). Both are Legal-approved wording — reuse it.
4. **The originator's announcements.** The contributing company's launch post,
   any foundation announcement with a co-founder, integrations with other
   protocols or platforms. This is the real timeline; LFX formation dates are
   when the LF record was created, not when the project began.
5. **Competitor and adjacent scan (web search).** `"<project>" vs`,
   `<project> alternative`, `<category> comparison`, `<each Premier member>
   <category>` (a member's own product in the same category is the one the
   interview forgets), `<project> extension`, `<project> integration <platform>`.
   A like-for-like alternative from a member needs the "peer, not enemy"
   treatment and cannot be left out.
6. **What members already built.** Directories, marketplaces, explorers, SDK
   listings — these fill case-study slots from public information and prove any
   "ecosystem" pillar.
7. **Standards and dates.** Any RFC, standard or "since 19xx" claim: open the
   primary document and record the publication month and year.

## Record it

Add to the Brand Kit's Appendix C a "Found beyond the brief" table:

```
| Item | Source (URL, date read) | Which document and section should use it | Why it matters |
```

Keep to items that change a claim, fill a TBD, or hand a persona its hook — ten
strong rows beat forty trivia rows — plus a dated timeline (origin, foundation
announcement, intent to launch, operational launch, major integrations) with a
source per row. The Message Foundation's origin story and Stat Bank, and the ICP
document's competitive landscape and persona hooks, are built from this table.
