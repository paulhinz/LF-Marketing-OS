# Sitemap guide

## Output format (plain text, always)

Present the sitemap as an indented outline: top-level bullets are pages (in nav order), nested bullets are sections in page order, each with a one-line content note and — in the draft shown at Gate 1 — the foundation-doc source that drove it.

```
* Home
   * Top Hero: [Title message from Message Foundation positioning; subtext = 25-word locked summary verbatim]
   * Section 2: Problem statement and why now [Message Foundation: pillar 1]
   * Section 3: Solution statement and benefits [Message Foundation: pillars 2-3]
   * Section 4: Who's who — members, adopters, community [ICP + gap answers]
   * Section 5: Key case studies / proof points [Message Foundation proof points + gap answer 2]
   * Section 6: Primary CTA banner [gap answer 1]
* Problem
   * Top Hero
   * Section 2: ...
* Solution
* Community / Upstream
* Join
   * CTA aligned to conversion goal — membership landing page, contributor guide, or download/get-started
```

## Standard page patterns for LF project sites

Choose pages based on the project's maturity and the conversion goal — a sitemap is an argument, not a template. Common set:

- **Home** — hero (positioning + locked summary), problem/why-now, solution/benefits, who's-who (members/adopters), proof (case studies, stats), CTA banner.
- **Problem / Why** — expands the problem narrative for visitors who need convincing; draws on Message Foundation pillars and talking points.
- **Solution / Technology / Framework** — what the project is and how it works; architecture overview; link out to docs (do not duplicate docs).
- **Community / Upstream** — how to contribute, governance summary, meeting calendars, code of conduct.
- **Members / Users** — logos (only with confirmed usage permission), tiers if membership-based, testimonials.
- **Case Studies / Adopters** — one page per strong story, or a single page when proof is thin (never pad).
- **News / Blog, Events** — ONLY if gap answer 3 confirmed a maintainer; otherwise omit.
- **Join / Get Started** — the conversion page; its content is dictated entirely by gap answer 1.
- **Charter-required pages** — Governance, TSC, Membership (per gap answer 4).

## Mapping foundation docs → pages

- **Message Foundation** → hero copy, boilerplate (footer/about), locked summaries (hero subtext, meta descriptions), messaging pillars (section themes), proof points, elevator pitch (Home flow), llms.txt.
- **Brand Kit** → voice/tone for all copy, visual direction inputs (Step 3), naming/terminology rules.
- **ICP & Target Markets** → which audiences get dedicated pages/sections, persona-specific CTAs, ordering of who's-who content.

## Gate 1 rules

- Present the full sitemap in one message; never trickle pages.
- Trace every page to its source (doc section or gap answer).
- ED edits are instructions, not suggestions — apply them exactly, then re-present the full revised sitemap.
- After the 3rd failed cycle, stop and recommend escalation to the Foundation Marketing Lead with a one-paragraph summary of the disagreement.
- On approval, save as `sitemap.md` in the project folder; it becomes the contract for Steps 3–4.
