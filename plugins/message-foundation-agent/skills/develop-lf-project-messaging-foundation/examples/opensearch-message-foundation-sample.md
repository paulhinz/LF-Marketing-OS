# OpenSearch Message Foundation (worked example)

> Generated during this skill's first test run, from the OpenSearch Brand Kit, the OpenSearch GitHub README, and a short interview. Included so future runs can see the expected shape and depth of output — not a template to copy verbatim.

## 1. Project Definition
OpenSearch is a community-driven, Apache 2.0-licensed open source search and analytics suite that makes it easy to ingest, search, visualize, and analyze data. It is an enterprise-grade search and observability platform, governed by the OpenSearch Software Foundation, a project of the Linux Foundation.

**Elevator pitch (long):** OpenSearch is the open source, Apache 2.0-licensed platform that brings search, real-time analytics, and observability together in one vendor-neutral system. Built for platform engineers, search teams, and reliability teams, it combines high-performance search with built-in hybrid and vector search and extensible ML tooling — so teams can build AI-ready applications without added licensing cost. Governed by the Linux Foundation and built by a global community, OpenSearch runs in production without vendor lock-in.

## 3. Positioning Statement
For platform engineers, search teams, and reliability teams who need fast, reliable information retrieval without vendor lock-in, OpenSearch is the open source search, analytics, and observability platform that delivers production-proven performance and built-in AI readiness — unlike closed, single-vendor search platforms, OpenSearch is governed by the Linux Foundation, licensed under Apache 2.0, and built in the open by a global community.

## Notable interview decisions from this run
- The Brand Kit's own document-architecture note initially scoped "Message Foundation Doc" narrowly (just the word-count derivatives). The user chose to keep the full framework *and* nest the derivatives inside it — flag this kind of conflict when it comes up rather than picking silently.
- Named adopters cited in the Brand Kit (specific enterprise customers) were swapped for generic, verifiable proof points (GitHub metrics, license terms, governance facts) on the user's instruction — always confirm before citing a named organization.
- Audience scope expanded mid-interview from three technical personas to include business champions and economic buyers once the user named five outreach objectives (awareness, membership, event attendance/sponsorship, education sales) — a good example of a gap-filling question paying off.
