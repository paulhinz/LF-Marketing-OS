# OpenSearch Target Markets and ICP (worked example)

> Generated during this skill's first test run, from the existing OpenSearch
> Brand Kit, OpenSearch Message Foundation Doc, the OpenSearch GitHub org
> profile, a live LFX query of OpenSearch Software Foundation membership
> records, and a short interview. Included so future runs can see the expected
> shape and depth of output — not a template to copy verbatim.

## 1.2 Competitive & Peer Landscape (excerpt)

Interview named: Elasticsearch/Elastic, ClickHouse, Typesense, Microsoft Azure
AI Search, Algolia. Each got a real category-position line (e.g. Elasticsearch
= "closest feature overlap; commercial licensing model, not Apache 2.0, for
parts of the stack") and a differentiation line grounded in the Brand Kit's
existing guardrails (Apache 2.0, no relicensing risk, vendor-neutral
governance) — not invented from nothing.

## 1.4 Current Member Segments (from live LFX data)

19 active OpenSearch Software Foundation memberships, tiered from a
`search_projects` + `search_members` query: Premier ($150K — AWS, IBM, SAP,
Uber), General 2,000+ (ByteDance, NetApp), General 500-1,999 (Canonical,
DigitalOcean), General 100-499 (Aiven, DTEX Systems), General 1-99 (8
OpenSearch-specialist vendors/consultancies), and one Associate member (CERN).
This is what "ground it in real data, don't invent a roster" looks like when
the live-data path is available.

## 2. ICP Definitions (structure, not full text)

Two ICPs, matching the existing Brand Kit/Message Foundation audience split:

- **ICP-A — Community & Technical Adopter Organization**: bottoms-up entry
  point, engineering-driven. Trigger events (from interview): new web
  app/SaaS build, scaling cost pain, security incident.
- **ICP-B — Enterprise Member Organization**: top-down, budget/governance-
  driven, sits above ICP-A once technical usage has proven value internally.

Disqualifiers: the interview answer was "unknown" — both ICPs' "Who is not an
ideal customer" fields were drafted as an **inferred pattern from the
competitive/firmographic evidence** and explicitly labeled as needing PL
confirmation, rather than invented and presented as settled.

## 3. Persona Definitions (5 total — 3 under ICP-A, 2 under ICP-B)

Reused, rather than reinvented, the audience definitions already in the Brand
Kit and Message Foundation Doc: Platform/Cloud Infrastructure Engineer,
Search/Search Relevance Engineer, and SRE/DevOps Reliability Engineer under
ICP-A; Business Champion and Economic Buyer under ICP-B. Each was extended to
the full Velocity Engine persona field set (Nickname, Works For, Trusted
Sources, Statements to share with the boss, etc.) — fields the Brand Kit/
Message Foundation didn't already define.

## 4. Fit & Warmth Scoring Inputs (excerpt)

Six attributes, weighted toward this cycle's named business outcome
(membership growth + event attendance): community engagement, organization
size & existing LF relationship, competitive displacement signal (using the
real named competitors), trigger-event presence, buying-committee
completeness (technical champion + economic buyer both identifiable), and
event/content engagement.

## Notable interview decisions from this run

- The user answered "unknown" to the disqualifiers question — the skill
  drafted inferred disqualifiers rather than leaving the field blank or
  inventing confident-sounding fake criteria, and flagged them clearly in
  Section 2 and again in Section 6 (Validation & Review) so a reviewer knows
  exactly what to check first.
- Live LFX membership data was available and used to ground Section 1.4 and
  the ICP-B firmographics in real company names and real membership tiers,
  rather than the more common fallback of writing illustrative example
  companies — always prefer the live-data path when the tools are available.
- Competitive set and trigger events came directly from the user, not
  generic-knowledge assumptions — both fed real content into Sections 1.2, 2,
  and 4 rather than staying abstract.
